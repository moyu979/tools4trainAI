# 03. 视频处理（压缩存储 + 训练转码）

> 本目录的 `video_processor.py` 为合并后的新工具，同时包含两种模式：
> **模式 A 压缩存储**（原「视频压缩存储」模块）与 **模式 B 训练转码**（原「训练转码」模块），
> 两个模块已合并于此。
> 旧的 `main.py`（仅训练转码）暂保留未删，其功能已被本脚本的模式 B 完全覆盖，确认新脚本实测正常后可删除。

## 用途

- **模式 A 压缩存储**：按码率分流，高码率视频压缩存档，保持原始分辨率
- **模式 B 训练转码**：全部转码为高度 640 等比例缩放，用于 AI 训练
- 两种模式共用：启动时自动检测本机可用的 H.264/HEVC 编码器并让用户自选

## 使用方式

```bash
python video_processor.py            # 交互式选择模式 / 路径 / 编码器
python video_processor.py --force    # 训练模式强制覆盖已存在的目标文件
```

流程：选择模式 → 输入源/缓存/目标目录 → 检测编码器（直接回车用默认）→ 确认 → 批量处理。
日志同时输出到终端和 `video_processing_时间戳.log`。支持 Ctrl+C 中断并清理不完整文件。

## 模式 A 压缩存储

- 码率 ≤ 50Mbps：直接复制（保持原扩展名与相对目录结构）
- 码率 > 50Mbps：压缩到 45Mbps / 峰值 70Mbps（HEVC，NVENC 与 AMF 用 10bit main10/p010le），
  保持原始分辨率，音频复制，**输出统一 .mp4**（规避 AVI 等容器装 HEVC 兼容性问题）
- 压缩失败回退为直接复制原文件（保持原扩展名）；可选缓存目录中转（先压缓存再移动，避免占用目标目录空间）

## 模式 B 训练转码

- 全部转码为高度 640 等比例缩放，输出 `.mp4`（音频 aac 128k）
- 已存在目标文件则跳过（`--force` 强制覆盖）
- 按已编码时长百分比显示进度

## 编码器检测优先级

```
NVIDIA NVENC(HEVC) → AMD AMF(HEVC) → Intel QSV(HEVC) → Apple VideoToolbox(HEVC)
→ Windows MF(HEVC) → CPU libx265 → CPU libx264
```

`ffmpeg -encoders` 列出的候选不代表本机可用（无 N 卡时 nvenc 仍会列出），
脚本会对每个候选实际编码一帧测试过滤，再让用户选择。

## 依赖

- FFmpeg / FFprobe（系统安装，需包含对应硬件编码器支持）
